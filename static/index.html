MICROSOFT GRAPH COLLECTION

Collect email by InternetMessageId

Download matching messages as subject-named MIME .eml files, preserve file attachments, and produce an Email_Report.csv in an analyst-selected local folder.

Authorization required

Application-level Mail.Read can read mail in every mailbox the app is allowed to access. Obtain written authorization, use the least access possible, protect the secret, and remove the temporary app registration or permission after collection.

Register the collection app

  1. In Microsoft Entra admin center, open Identity → Applications → App registrations → New registration.
  2. Name the app (for example, M365-Email-Collector), select the appropriate tenant scope—normally single tenant—and register it.
  3. Copy the Directory (tenant) ID and Application (client) ID from Overview.
  4. Open Certificates & secrets → New client secret. Copy the secret Value immediately; do not enter its Secret ID below.
  5. Open API permissions → Add a permission → Microsoft Graph → Application permissions. Add Mail.Read, then have an administrator grant tenant-wide consent.
  6. Where possible, restrict the app to only the approved mailboxes. After validating the output, delete the secret/app or revoke its permission.

ANALYST GUIDE

M365 Investigator Suite documentation

Complete reference for case management, UAL and Message Trace review, evidence enrichment, hunting, email collection, and analyst deliverables.

1. Cases and navigation

Create an empty investigation case from All cases, then add evidence from inside it. Recent Cases shows the case name, current UAL row count, and creation time. Deleting a case moves its local source evidence, parsed rows, tags, and derived analysis to recoverable system trash.

The collapsible left sidebar opens UAL Review, MTL Review, Email Collection, Client XLSX, and this guide. Each case can hold multiple independent UAL and MTL datasets.

2. UAL uploads and parsing

UAL Review accepts Purview CSV, Excel, JSON, and JSONL exports. Add and name multiple exports, switch them with the dataset selector, or delete one without affecting the others.

The parser retains original fields and flattens JSON in AuditData into reviewable columns. Malformed payloads are preserved with parse-error context. Each dataset keeps separate filters, column choices, tags, IP cache, message analysis, hunts, app mappings, and Event narratives.

3. UAL views and live metrics

Category chips provide default views for Login activity, Inbox rules, File activity, Mail activity, and Teams activity. The next chip row categorizes the matching Operation values. Selecting an operation resets conflicting category state.

Category counts, operation counts, Rows, Fields, Users, IP indicators, and Message IDs update against the current query. Category views select useful forensic defaults such as all populated SessionId fields, login AppId/device posture fields, inbox-rule details, file paths, mail identifiers, and Teams context.

4. Query language

Use field:value for partial matching and field:=value for exact matching. Field names and values are case-insensitive. Adjacent terms mean AND; explicit AND/&& and OR/|| are supported. AND takes priority, so use parentheses for mixed expressions. Prefix a term with - to exclude it.

user:=alice@contoso.com AND operation:*Login*
(ip:=1.2.3.4 OR ip:=5.6.7.8)
-result:=Failed
"invoice 2026"

5. Wildcards, empty values, and ranges

* matches any characters. An exact empty comparison matches blank or missing values; excluding empty keeps populated rows. Use >, <, >=, and <= for timestamps and numbers.

ip:64.*
Login.DeviceName:=""
time:>=2026-07-21T12:00:00Z
time:<2026-07-22T00:00:00Z
_Row:>=100 AND _Row:<=500

Right-click a timestamp, or open its value drawer, to add an after/before filter directly.

6. Aliases

user       → identity/mailbox fields
time       → CreationTime
ip         → known IP/address fields
clientip   → client IP fields
operation  → Operation
messageid  → message identifier fields
result     → status/result fields
workload   → Workload
recordtype → RecordType

Full flattened field names—such as Login.DeviceName—can always be queried directly.

7. Table review controls

  • Show 50, 100, 250, or 500 rows per page; use Previous/Next for paging.
  • Click row number, CreationTime, Received, or any timestamp/date column to switch ascending and descending order. Hunt risk and score columns are sortable too.
  • Drag headers to reorder. Right-click a header to view unique values, freeze/unfreeze it, hide it, pin it first, move it, or copy its name. Freezing moves the column to the left and keeps it visible during horizontal scrolling.
  • The Columns drawer changes visible fields and keeps Apply columns accessible. Entirely empty dataset columns are omitted to reduce noise.

8. Values and direct filtering

Click a cell to open its complete value and related actions. Right-click a cell to include/exclude that value, tag the row, copy the value, or open full details. Sender and recipient values in MTL can open the extracted domain in DomainTools WHOIS.

View unique values shows value counts—including (empty)—for the complete current result set. Search the list, select multiple include/exclude values, and use Apply selected to add one grouped query instead of running after every click.

9. Rows of interest

In UAL or MTL, mark or unmark an individual row from its cell menu/value drawer. Tagged rows are highlighted and persist within the selected dataset. Use Tagged to isolate all marked rows.

After applying a query, UAL category, or UAL operation filter, Tag filtered rows marks every matching row across all pages. When the complete matching set is already tagged, it becomes Untag filtered rows so bulk tagging can be reversed.

10. Filtered IP enrichment

Enrich IPs applies only to rows matching the current query/category/operation; MTL has the same filtered behavior. Choose a source field or use auto-detection. Select the anonymous free endpoint or enter a commercial IP-API key for the HTTPS Pro endpoint. Keys are used only for the active request and are not saved or returned. Results persist after clearing filters and after reopening the case.

Added columns are ordered Country, Region, City, ISP, AS, Mobile, VPN/TOR, and Hosting. Private, loopback, link-local, and invalid addresses are classified locally. Only unique public IPs are submitted and cached, so subsequent uses do not repeat completed lookups.

11. Login hunts

Both login hunts require IP enrichment and open a configuration drawer before analysis. Hunt Suspicious Logins can flag activity outside an editable trusted-country list and selected proxy/VPN/TOR or hosting signals. Device-posture requirements and the treatment of missing compliance values are configurable.

Hunt Impossible Travel compares consecutive logins per user using editable country-change, region-change, and elevated-risk time windows. Hosting, proxy/VPN/TOR, and device posture can be enabled independently for the elevated-risk rule. Review all scores and reasons as leads—not verdicts.

12. UAL forensic actions

  • Extract Message IDs: finds InternetMessageIds and normalizes them with angle brackets.
  • Message + Subjects: persistently associates IDs and subjects from flattened or nested audit payloads; unmatched IDs remain with (no subject).
  • Map App IDs: resolves populated AppId/ApplicationId variants against the bundled Microsoft first-party reference without sending case data externally.
  • Generate Events: writes a persistent, tracker-ready narrative to Event for every currently filtered row. Login narratives stop after actor, IP, location/ISP, and true Hosting/VPN signals; timestamps stay in their own columns.

13. MTL datasets and review

MTL Review accepts multiple named Exchange Message Trace CSVs, including UTF-8 and UTF-16 exports. Common sender, recipient, subject, status, message/network ID, Received, and IP headers are normalized while original columns remain available.

Each trace has independent queries, paging, sorting, frozen/visible columns, tags, IP/domain enrichment, suspicious-mail results, and generated Events. Live metrics report matching rows, fields, senders, recipients, and IPs.

14. MTL domain and mail hunting

Enrich domains operates on current filtered rows and submits only extracted sender/recipient domains—not full addresses—to IANA-discovered RDAP services. It adds registered domain, registrar, registration/expiration/change dates, status, name servers, DNSSEC, lookup status, and errors.

Hunt suspicious mail requires domain enrichment first. Configure maximum domain age or a registration-date range, edit phishing-subject keywords, and enable the editable third-party survey/messaging sender-domain list. SurveyMonkey-family domains are included by default to surface messages sent through that legitimate platform for review. One signal is Medium; two or more are High. MessageTraceHunt.ServiceDomains and MessageTraceHunt.SuspiciousReason record what matched. A service-domain match is an investigation lead, not proof of phishing.

15. MTL Events

Generate Events creates persistent values only for the current filtered MTL rows using the compact format Subject: …; Sender: …; Recipient: …. Repeating the action on another filtered set adds those rows without removing earlier Events.

16. Email Collection

Register a temporary Entra app, grant Microsoft Graph application permission Mail.Read with administrator consent, and enter the Directory (tenant) ID, Application (client) ID, client-secret value, and an absolute output folder.

Collect one mailbox with one or more manually entered InternetMessageIds, or upload CSV with exactly MailboxOwnerUPN and InternetMessageId. IDs receive angle brackets when missing. Matching messages are saved as subject-named MIME .eml files with file attachments and Email_Report.csv. Not-found/error targets do not stop the remaining collection.

Obtain written authorization, restrict access where possible, and remove the temporary app/secret or permission afterward. The secret is used only for the request, cleared from the form, and never persisted or returned.

17. CSV and XLSX deliverables

Export CSV in UAL or MTL Review exports the complete current filtered result—not only the displayed page—and lets the analyst choose a safe filename. Derived and enriched columns currently present in the result are included.

Client XLSX accepts any CSV, removes fully empty rows and columns, creates a native filtered Excel table using blue Table Style Medium 2, freezes the header, sizes populated columns, hides worksheet cells outside the table, and writes values as text to preserve identifiers and reduce formula-injection risk.

18. Local storage and external services

Cases, source evidence, tags, caches, and derived analysis stay under local cases/; the tool has no analytics or telemetry. Source files and common evidence/output formats are excluded by Git rules. Review staged files and history before publishing.

Free IP enrichment sends accepted public IPs to the anonymous HTTP endpoint under its non-commercial terms. Commercial mode sends public IPs and the request-only key over HTTPS to the Pro endpoint. Domain enrichment sends domains over HTTPS to public RDAP services. Email Collection sends the requested mailbox/ID operations to Microsoft identity and Graph endpoints. Review the free terms, Pro terms, and your organization’s evidence-handling requirements.

19. Recommended investigation workflow

  1. Create a case and add each evidence export as a clearly named dataset.
  2. Preserve source files, record authorization, and validate dataset row counts.
  3. Narrow with category chips, queries, unique values, and time ranges.
  4. Tag notable rows before enrichment or hunts.
  5. Enrich only the filtered evidence needed, then run the relevant hunt.
  6. Generate Event narratives and export filtered evidence or a client XLSX.
  7. Validate automated findings against surrounding logs; hunts identify leads and can produce false positives.
